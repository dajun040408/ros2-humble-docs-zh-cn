为 ROS 2 功能包编写文档
########################

.. contents:: 目录
   :depth: 2
   :local:

本指南介绍为 ROS 2 功能包创建文档的标准方法。对于已发布二进制软件包的功能包，生成的文档也会托管在 `docs.ros.org/en/<distro>/p/<package>/`。有关如何为 docs.ros.org 上的文档做出贡献，请参阅 :doc:`为 ROS 2 文档做贡献 <../The-ROS2-Project/Contributing/Contributing-To-ROS-2-Documentation>`。

前置条件
--------

- :doc:`安装 ROS <../../Installation>`。
- `安装 rosdoc2 <https://github.com/ros-infrastructure/rosdoc2#installation>`_。

功能包文档概述
--------------

本指南讨论的文档类型称为“功能包文档”或“API 文档”。对于已发布到 ROS Index 的 ROS 功能包，其文档会在 ROS 构建农场上构建，托管在 docs.ros.org，并通过 index.ros.org 页面上的 `API Docs` 按钮访问。

负责生成 ROS 2 功能包文档的工具是 `rosdoc2 <https://github.com/ros-infrastructure/rosdoc2>`_。

`rosdoc2` 是常用文档框架 `Sphinx <https://www.sphinx-doc.org/>`_ 的便捷封装。Sphinx 既支持自由格式的文本文档，也支持根据代码注释生成 Python API 文档。`breathe <https://breathe.readthedocs.io/en/latest/>`_ 和 `exhale <https://exhale.readthedocs.io/en/latest/>`_ 软件包可以将 Doxygen 集成进来，从而加入自动生成的 C++ API 文档。

如果功能包没有任何文档或配置，`rosdoc2` 会创建默认配置，并应用统一主题及与其他功能包集成所需的选项。

构建功能包文档
--------------

要使用 `rosdoc2` 将功能包文档生成为 HTML 格式，请运行：

.. code-block:: console

   $ rosdoc2 build --package-path <package-path>

生成的文档写入 `docs_output/<package-name>/index.html`，可以使用浏览器查看。

配置
----

ROS 功能包文档有三个配置位置：用于通用设置的 `rosdoc2.yaml`、用于 Sphinx 设置的 `conf.py`，以及用于 Doxygen 设置的 `Doxyfile`。如果这些文件不存在，都会采用或生成默认配置，因此它们都不是严格必需的。不过，如果需要使用自定义文本页面等功能，可能需要创建并修改这些文件。

rosdoc2.yaml
^^^^^^^^^^^^

这是 rosdoc2 的主要入口配置文件。它指定通用设置，可以控制特定构建器（Doxygen 和 Sphinx）的执行，并决定运行哪些构建器。

`rosdoc2` 提供了许多配置选项，可以通过 `rosdoc2.yaml` 文件调整。要生成默认配置文件并在此基础上自定义，请运行：

.. code-block:: console

   $ rosdoc2 default_config --package-path <package-path>

然后在 `package.xml` 的 export 部分添加 `<rosdoc2>rosdoc2.yaml</rosdoc2>`：

.. code-block:: xml

    <package>
        <!-- [...] -->
        <export>
            <!-- [...] -->
            <rosdoc2>rosdoc2.yaml</rosdoc2>
        </export>
    </package>

不过，对于大多数功能包，`rosdoc2` 的默认设置已经足够，无需自定义配置。更多信息请参阅 `rosdoc2 README <https://github.com/ros-infrastructure/rosdoc2#using-a-rosdoc2yaml-file-to-control-how-your-package-is-documented>`__。

conf.py、rosdoc2_settings
^^^^^^^^^^^^^^^^^^^^^^^^^

功能包文档的最终输出几乎总是由 Sphinx 构建。每个 Sphinx 项目都通过 `doc` 目录中的 `conf.py` 文件配置。

如果不存在配置文件，构建文档时会创建并使用默认 Sphinx 项目。如果功能包的 `doc` 子目录中存在 `conf.py`，则会使用该配置。

如果希望包含独立的 reStructuredText 文档页面，则必须创建自定义 Sphinx 项目。独立文档页面可以列出多个教程和指南；如果希望在功能包文档中实现这一点，就需要创建自定义 Sphinx 项目。

`rosdoc2` 会向 `conf.py` 添加额外设置，并覆盖其中部分设置。Sphinx 设置变更的信息会以 `[rosdoc2]` 前缀记录到控制台。

Doxyfile
^^^^^^^^

Doxygen 是一种根据代码注释自动生成 C++ API 文档的工具。虽然 Doxygen 也可以直接生成 HTML，但在 ROS 功能包的常见工作流中，Doxygen 会生成机器可读的 XML，然后由 Sphinx 读取并与其余文档集成。

也可以在 `rosdoc2.yaml` 中只启用 Doxygen 构建器来生成纯 Doxygen 文档，但这种情况并不常见。

自定义 Sphinx 文档
------------------

创建 Sphinx 项目
^^^^^^^^^^^^^^^^

如果希望在自动生成的 API 文档之外添加独立文档页面，就需要创建自定义 Sphinx 项目。该项目应放在功能包目录下名为 `doc` 的子目录中。

可以在 `doc` 目录中运行 `sphinx-quickstart` 创建新的 Sphinx 项目，并在“Separate source and build directories”问题中选择 `no`。向导要求输入项目名称、作者和版本，但之后可以删除这些信息，因为 `rosdoc2` 会根据功能包的 `package.xml` 将其提供给 Sphinx。

更多信息请参阅 `Sphinx quickstart <https://www.sphinx-doc.org/en/master/usage/quickstart.html>`_。

自定义 index.rst
^^^^^^^^^^^^^^^^

`sphinx-quickstart` 向导会创建 `index.rst` 文件。它是功能包的自定义首页，作用类似 GitHub 上的 `README` 文件。

添加 Python API 文档
^^^^^^^^^^^^^^^^^^^^

默认情况下，`rosdoc2` 使用 `sphinx-apidoc` 工具和 Sphinx 的 `autodoc` 扩展，自动为 Python 代码生成文档。

为了让 autodoc 找到功能包中的 Python 模块，必须在 `conf.py` 中将其加入 Python 搜索路径：

.. code-block:: python

    sys.path.insert(0, os.path.abspath('.'))

这是因为 `rosdoc2` 会使用脚本中的其他配置包装自定义 `conf.py`。在这种情况下，由于 rosdoc2 与 conf.py 的交互，`os.path.abspath` 中的 `.` 指向功能包根目录，而不是功能包的 `doc` 目录。

默认情况下，功能包 API 文档已经可以通过首页上的“Module Index”链接访问。如果还希望 API 文档显示在目录中，只需在 `index.rst` 中添加指向 `modules` 页面 的链接：

.. code-block:: rst

    .. toctree::
       :maxdepth: 2
       :caption: Contents:

       Python Modules <modules>

添加 C++ API 文档
^^^^^^^^^^^^^^^^^

如果希望将自动生成的 API 文档添加到自定义首页，请在希望显示 API 文档的位置添加 `generated/index`：

.. code-block:: rst

   .. toctree::
      :maxdepth: 2

      C++ API Docs <generated/index>

这会在侧边栏目录中添加“Class Hierarchy”“File Hierarchy”和“Reference”等条目。

如果希望将它们归到一个“C++ API Docs”标题下，避免侧边栏过于杂乱，可以创建一个单独的文件，例如 `cpp_api_docs.rst`，并链接到生成的文档：

.. code-block:: rst
    :caption: cpp_api_docs.rst

    C++ API Docs
    ============

    These are the autogenerated docs for the internal implementation.

    .. toctree::
       :maxdepth: 3
       :caption: Contents:

       generated/index

然后还需要在 `index.rst` 中添加该文件，才能让它出现在侧边栏：

.. code-block:: rst
    :caption: index.rst

    .. toctree::
       :maxdepth: 2
       :caption: Contents:

       cpp_api_docs

包含已有 README.md
------------------

如果 Git 仓库中已经有 `README.md`，可以直接将其用作文档首页，而无需重复维护内容。为了在 Sphinx 中正确包含 Markdown 文件，并保留相对链接和图片路径，需要额外处理。

首先，在 `index.rst` 旁边创建代理文件 `readme_include.md`。该 Markdown 文件只负责包含原始 README.md，同时保留相对图片路径，避免下一步中图片路径失效：

.. code-block:: markdown
    :caption: readme_include.md

    ```{include} ../README.md
    :relative-images:
    ```

然后，在 `index.rst` 中使用 myst 将该文件包含进来：

.. code-block:: rst
    :caption: index.rst

    .. include:: readme_include.md
       :parser: myst_parser.sphinx_

还需要在 `conf.py` 的扩展列表中添加 `myst_parser`：

.. code-block:: python
    :caption: conf.py

    extensions = ["myst_parser"]

CI 与 docs.ros.org
------------------

ROS 构建农场使用 `rosdoc2` 构建功能包文档，并托管在 `docs.ros.org/en/<distro>/p/<package>/`。

要启用此功能，必须在 `rosdistro/{DISTRO}/distribution.yaml` 中配置包含文档的代码仓库。通常这就是功能包的源码仓库：

.. code-block:: yaml

      <package_name>:
        doc:
          type: git
          url: https://github.com/<github_username>/<package_name>.git
          version: main
        release:
        [...]

构建农场会为每个发行版分别托管文档，并定期从指定分支的最新提交重新构建。更新托管文档不需要创建新的软件包发行版。

要查看功能包文档构建状态，可以在 `https://build.ros2.org` 中搜索 `doc__<package_name>`。每个已发布该功能包的发行版都会创建一个任务。在任务页面中，可以查看最近一次构建触发时间、构建状态和日志。
