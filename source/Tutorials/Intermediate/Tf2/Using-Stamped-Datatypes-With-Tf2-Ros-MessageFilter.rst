在 tf2_ros 中使用带时间戳的数据类型和 MessageFilter
====================================================

**目标：** 学习如何使用 §tf2_ros::MessageFilter§，仅在所需坐标变换可用时处理传感器消息。

**教程级别：** 中级

.. contents:: 目录
   :depth: 2
   :local:

背景
----

传感器消息通常带有时间戳和坐标系信息。处理这类消息时，必须确保消息对应的坐标变换已经到达 tf2 缓冲区。若消息先于变换到达，直接查询变换可能失败。

§tf2_ros::MessageFilter§ 是一个消息过滤器，可缓存消息，直到对应坐标变换可用，再将消息传递给回调函数。这样可以避免在传感器数据和 TF 数据到达顺序不同的情况下丢失可处理的数据。

核心概念
--------

带时间戳的消息通常使用 §std_msgs::msg::Header§ 描述消息时间戳和 §frame_id§。tf2 根据消息时间戳查询对应时刻的变换，而不是简单使用最新变换。

§MessageFilter§ 将消息订阅与 tf2 缓冲区关联起来。只有当消息从源坐标系变换到目标坐标系所需的数据可用时，过滤器才会调用注册的回调。

使用步骤
--------

1. 创建 tf2 缓冲区和监听器：

.. code-block:: cpp

   tf2_ros::Buffer tf_buffer(node->get_clock());
   tf2_ros::TransformListener tf_listener(tf_buffer);

2. 创建消息过滤器时，指定目标坐标系、缓存容量、缓冲区和节点接口。过滤器会等待所需变换到达。

3. 将传感器订阅与过滤器连接，并注册消息回调。回调收到消息时，意味着过滤器已确认目标变换可用。

使用注意事项
------------

* 目标坐标系必须存在于 TF 树中。
* 消息的时间戳应与传感器数据采集时间一致。
* 缓存容量应根据消息频率和 TF 延迟合理设置。
* 若变换长时间未到达，消息可能因缓存容量限制而被丢弃。
* 应检查 frame_id 是否正确，避免坐标系名称不一致导致过滤器一直等待。

总结
----

§tf2_ros::MessageFilter§ 将传感器消息处理与 TF 变换可用性关联起来，使节点能够在对应坐标变换到达后再处理消息，适用于激光雷达、相机和其他带时间戳的传感器数据流。
