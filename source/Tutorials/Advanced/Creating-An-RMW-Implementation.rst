创建 rmw 实现
==============

**目标：** 学习如何为特定中间件创建新的 §rmw§ 实现，从底层中间件所需特性到 RMW 接口实现细节。

**教程级别：** 高级 | **预计时间：** 30 分钟以上

.. contents:: 目录
   :local:

简介
----

ROS 2 架构包含两个主要抽象层：

#. 客户端库接口 §rcl§：为 §rclcpp§ 和 §rclpy§ 等用户接口提供支持。
#. 中间件接口 §rmw§：抽象底层中间件实现，例如特定 DDS 实现或 Zenoh。

§rmw§ API 包含函数级文档，但缺少对接口特性以及底层中间件需要满足哪些要求的高层说明。

本指南面向希望为特定中间件实现 §rmw§ 接口的开发者。内容首先介绍 rmw 接口及其工作方式，然后说明中间件实现必须支持的主要概念和功能，最后介绍实现细节，包括创建实现骨架和编写接口函数的建议。

.. note::

   §design.ros2.org§ 上的 ROS 2 设计文章属于历史文档，可能无法反映 ROS 2 当前状态。但在某些情况下，它们仍可提供有价值的背景信息。

rmw 接口
--------

§rmw§ 接口由 §rmw§ 功能包中的 C 头文件声明。各个 rmw 实现作为独立功能包，为这些 C 函数提供具体实现。例如，§rmw_fastrtps_cpp§ 为 eProsima Fast DDS 实现该接口。

创建新的 rmw 实现时，需要理解接口函数的语义、资源生命周期、错误处理和线程安全要求，而不仅仅是逐个实现函数签名。

中间件能力
----------

底层中间件需要支持 ROS 2 所需的通信能力，包括节点发现、发布订阅、服务、动作、QoS、序列化和类型支持等。不同中间件的能力和限制可能不同，RMW 实现需要在接口层正确映射这些行为。

实现骨架
--------

通常应从现有 RMW 实现的结构入手，创建独立功能包，并按接口头文件逐步实现函数。建议先实现初始化、节点、发布者和订阅者等基础功能，再逐步补充服务、事件、QoS 和图信息等能力。

测试与兼容性
------------

新的 RMW 实现需要验证接口行为、资源释放、并发访问、错误路径和 QoS 语义。应使用 ROS 2 中间件测试套件，并与客户端库和常见 ROS 2 功能包进行集成验证。

总结
----

实现新的 RMW 不只是封装底层传输 API，还需要正确实现 ROS 2 对发现、通信、QoS、资源生命周期和错误处理的语义。本指南是开发新 RMW 实现的入门入口。
