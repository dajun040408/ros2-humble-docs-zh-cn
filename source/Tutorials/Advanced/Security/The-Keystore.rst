理解 ROS 2 安全密钥库
=====================

**目标：** 了解 ROS 2 安全密钥库中的文件。

**教程级别：** 高级 | **预计时间：** 15 分钟

.. contents:: 目录
   :depth: 2
   :local:

背景
----

§sros2§ 软件包可用于创建启用 ROS 2 安全机制所需的密钥、证书和策略。安全配置具有很高的灵活性。理解 ROS 2 Security Keystore，有助于将其集成到现有 PKI（公钥基础设施）中，并按照组织安全策略管理敏感密钥材料。

安全文件的位置
--------------

在前面的教程中启用通信安全后，可以检查启用安全功能时创建的文件。这些文件使加密通信成为可能。

§sros2§ 工具（§ros2 security ...§）会将文件分为公共、私有和 enclave 密钥材料。

ROS 使用环境变量 §ROS_SECURITY_KEYSTORE§ 指定密钥库目录。本教程示例使用 §~/sros2_demo/demo_keystore§。

公共密钥材料
^^^^^^^^^^^^

公共目录中包含加密证书。身份和权限证书通常链接到证书颁发机构（CA）证书。

在 PKI 中，§Certificate Authority§ 是信任锚，用于验证参与者的身份和权限。对于 ROS，这意味着参与 ROS 计算图的所有节点都可以建立相互信任关系。将 CA 证书 §ca.cert.pem§ 放置在机器人上的正确位置后，使用同一 CA 的 ROS 节点就可以相互验证。

教程中可能会临时创建 CA，但生产系统应根据预先制定的安全计划创建 CA。通常生产环境中的 CA 会离线创建，并在设备初始配置时部署到机器人上。CA 可以每台机器人独立配置，也可以由一组互相信任的机器人共享。

DDS（以及 ROS）支持将身份信任链和权限信任链分离，因此两种功能可以使用不同的证书颁发机构。多数 ROS 系统安全计划不要求分离，因此安全工具通常会生成一个同时用于身份和权限的 CA。

可以使用 §openssl§ 查看 X.509 证书：

.. code-block:: console

   $ cd ~/sros2_demo/demo_keys/public
   $ openssl x509 -in ca.cert.pem -text -noout

CA 证书需要注意：

* 证书主题名称 §sros2CA§ 是 sros2 工具提供的默认值。
* 证书从创建之日起有效期为十年。
* 证书包含用于公钥/私钥加密的公钥。
* 根 CA 证书是自签名证书，即使用自己的私钥签名。

由于这是公共证书，可以根据需要复制到 ROS 系统中的其他设备，以建立信任关系。

私有密钥材料
^^^^^^^^^^^^

私有密钥材料包含敏感信息，必须严格限制访问权限。不得像公共 CA 证书一样随意复制或分发私钥。应根据组织的密钥管理策略保护、备份和轮换私有密钥。

Enclave 密钥材料
^^^^^^^^^^^^^^^^

Enclave 对应 ROS 节点或节点集合的安全身份和权限配置。每个 enclave 可以包含自己的身份证书、私钥和权限文件。部署时应确保节点只能访问其自身所需的密钥材料。

总结
----

ROS 2 安全密钥库包含公共、私有和 enclave 密钥材料。理解 CA 证书、身份和权限信任链，以及私钥保护方式，是将 ROS 2 Security 集成到生产系统的重要基础。
