发行版开发流程
==============

.. contents:: 目录
   :depth: 2
   :local:

每个 ROS 2 发行版都要经历一年多的开发流程，而且新发行版的开发通常会在上一个发行版发布之前就开始。

下面从较高层面介绍这一开发流程。流程中的各项工作没有严格规定的截止日期，但通常应先完成前面的工作，再开展后续工作。

有关某个具体发行版的流程进度，请参阅该发行版的文档页面。

.. list-table::
   :class: release-process
   :header-rows: 1
   :widths: 30 70

   * - 工作事项
     - 说明
   * - 确定 ROS Boss
     - ROS Boss 负责推动某个发行版完成开发、发布、更新以及生命周期结束（EOL）等阶段。该人员由 ROS PMC 选出。
   * - 执行发行版命名流程
     - ROS Boss 负责组织发行版命名过程，并参考社区意见及潜在名称冲突等因素。
   * - 创建发行版文档页面
     - 每个发行版都需要一个文档页面，列出计划发布日期、EOL 日期，以及相较上一个发行版的重要变化等基本信息。
   * - 制定发行时间表
     - 发布日前的最后几周通常非常紧张，存在许多截止日期，例如默认 RMW 实现冻结时间。这些截止日期必须提前规划。
   * - 制定路线图
     - ROS 的每位贡献者可能都有自己计划在该发行版中实现的功能。我们会尽量维护一份整体路线图，列出预计加入发行版的新功能和重要变更。ROS Boss 和 ROS 项目负责人会与 ROS PMC、OSRA TGC 及其他相关方合作，制定能够在可用时间内完成、并满足 ROS 社区需求的路线图。
   * - 发布路线图公告
     - 计划实现的功能和重要变更会通过 GitHub Issue 公开，并跟踪路线图中各项工作的进度。当然，路线图并非从此固定不变。开发计划可能发生变化，我们始终欢迎新的贡献，即使它们不在原计划路线图中。
   * - 确定目标平台和主要依赖项
     - 必须提前确定目标操作系统、发行版及版本，以便基础设施（例如构建农场支持）有足够时间完成开发。同样，还必须确定各项主要依赖的版本，例如 Python、编译器、Eigen 等。这些内容通过更新 `REP-2000 <https://reps.openrobotics.org/rep-2000/>`_ 确定。
   * - 为构建农场增加平台支持
     - 构建农场是支持 ROS 2 发行版的重要基础设施。它提供持续集成功能，帮助维护项目质量，并构建社区依赖的二进制软件包，使用户不必从源码构建 ROS 2 及其软件包。如果目标平台与上一个 ROS 2 发行版不同，就必须为构建农场增加相应支持。
   * - 委托设计 Logo 和相关美术作品
     - Logo 是每个 ROS 2 发行版的重要组成部分。专业艺术家会根据选定的发行版名称设计 Logo，并据此制作 turtlesim 图标等其他美术作品。
   * - 为发行版创建邮件列表
     - 必须建立邮件列表，以便向关注该发行版的人员发送重要公告，例如通知用户其软件包无法在构建农场上构建为二进制包。
   * - 创建测试用例
     - 在开发流程进入最后几个月时，测试工作将全面展开。必须提前创建最终开发阶段使用的集成测试用例，并交给负责执行测试的发布团队。
   * - 发布即将冻结 RMW 的公告
     - RMW 冻结是指新发行版的默认 RMW 实现进入功能冻结阶段。这为开发者提供了稳定的测试目标，尤其对客户端库开发者十分重要，因为他们需要了解 RMW 层将提供哪些功能。
   * - 升级依赖软件包
     - ROS 依赖但并非 ROS 软件本身、且目标平台包管理器（例如 Ubuntu 的 aptitude）中没有提供的依赖项，称为 vendor packages。必须将这些软件包升级到 REP-2000 指定的版本，或升级到适当版本。这一点在 Windows 上尤其重要。
   * - 制定详细的发行计划
     - 对开发流程最后两个月进行规划，形成详细测试计划、特定软件包必须可用的时间表等。这样可以确定发行流程各步骤之间的依赖关系，并安排人员执行相应工作。
   * - 冻结 RMW
     - RMW 实现进入功能冻结阶段。理论上，此时可以进行全面测试，确保其在正式发布日期前正常工作。
   * - 发布即将整体冻结的公告
     - 冻结 RMW 后的下一步是冻结整个发行版。此时 ROS 核心软件包进入功能冻结阶段，为非核心软件包开发者提供稳定的测试目标，也为发行版测试人员提供不会在测试后立即发生变化的测试版本。
   * - 冻结发行版
     - 从此时起，不能再向任何 ROS 核心软件包添加新功能。代码库中只允许合并密集集成测试阶段发现的缺陷修复。此时 Rolling Ridley 实际上也会暂时冻结。
   * - 发布即将创建分支的公告
     - 从 Rolling Ridley 创建新的 ROS 2 发行版分支是一个重要节点，应提前做好准备。
   * - 发布即将进入 Beta 阶段的公告
     - 新发行版进入 Beta 阶段后，已经可以开展更广泛的测试。我们会邀请整个 ROS 社区参与测试。测试人员越多越好，因为需要覆盖尽可能多的场景，在正式发布前发现缺陷。
   * - 从 Rolling Ridley 创建分支
     - 通过从 Rolling Ridley 创建新分支，正式建立新的 ROS 2 发行版。此时，新发行版诞生，而 Rolling Ridley 则脱离本次发行流程，可以继续向前发展并重新接收新功能。
   * - 将发行版添加到 CI
     - 更新持续集成系统，使其能够使用新发行版的分支和 ROS 核心软件包进行构建。这样，软件包开发者就可以针对新发行版运行 CI，而不必继续针对 Rolling Ridley。
   * - 开始构建临时测试归档包
     - 负责全面测试新发行版的测试团队需要可直接使用的测试内容，避免不断从源码编译 ROS 2。此时会使用构建农场生成特定时间点的发行版归档包，供测试人员使用。
   * - 添加发行版文档
     - 将该发行版的详细文档添加到 ROS 2 文档网站，例如相较上一个发行版的重要变化。
   * - 发布 Beta 公告
     - 正式发布发行版 Beta 版本，并邀请整个 ROS 社区参与测试。此时需要尽可能广泛的测试场景，以便在正式发布前发现缺陷。
   * - 最终发布准备
     - 当新发行版进入全面冻结阶段时，开始进行最终发布准备工作，包括使用构建农场生成二进制软件包，确保正式发布时有可用的软件包。
   * - 正式发布
     - 正式发布日通常计划与 5 月 23 日世界海龟日重合。发行版二进制软件包会放入发布软件源，并发布公告。社区会举行庆祝活动，ROS 2 开发团队也可以稍作休息。
